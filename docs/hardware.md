# Профиль оборудования и результаты

## Профиль

Замер выполнен на локальной машине с Python 3.12. Модель и параметры запуска
задаются в `params.yaml`; итоговые значения ниже нужно обновить после запуска
`make bench` на машине сдающего.

Модель: `Qwen/Qwen3-0.6B`. Использован GPU-профиль: NVIDIA GeForce RTX 4060 Ti
с 8 ГБ VRAM. Модель загружена на `cuda:0` в формате `bfloat16`.

## Результаты замера

Команда `make bench` записывает три независимых показателя в
`docs/bench.json`:

- `load_time_sec` — время загрузки токенизатора и модели;
- `tokens_per_sec` — медианная скорость генерации после прогрева;
- `peak_rss_mb` — пиковая RSS-память процесса.

Замер выполнен командой `make bench` через Python 3.12 на GPU:

| Показатель | Значение |
| --- | ---: |
| Время загрузки, с | 7.77 |
| Скорость, токенов/с | 39.20 |
| Пиковая RSS, МБ | 2084.8 |

## Разбор найденных дефектов

### 1. Имя модели было захардкожено

Имя `Qwen/Qwen3-0.6B` находилось непосредственно в коде загрузки,
генерации и отчёта бенчмарка. Поэтому изменение `model.name` в `params.yaml`
не меняло реально загружаемую модель. Теперь `load_model`, генерация и отчёт
используют `params["model"]["name"]`, а имя модели живёт только в конфиге.

### 2. Зависимости не имели версий

В `pyproject.toml` были указаны только имена пакетов. Это позволяло получить
разные версии `torch` и `transformers` на разных машинах и ломало повторяемость
окружения. Теперь все прямые зависимости имеют зафиксированные версии, а
`uv.lock` фиксирует полный граф зависимостей.

### 3. В tokens/sec попадала загрузка модели

Старый таймер запускался до `load_model`, поэтому первое значение скорости
включало дорогую и не относящуюся к генерации загрузку. Теперь время загрузки
измеряется отдельно, перед замерами выполняется прогрев, а каждый measured run
имеет собственный таймер только вокруг `generate`.

### 4. Генерация не была воспроизводимой

В конфиге был указан seed, но он нигде не применялся, а sampling был включён
при ненулевой temperature. Теперь перед запуском фиксируются random, NumPy и
PyTorch через `set_seed`, поэтому повторные запуски используют одинаковое
случайное состояние и дают одинаковый результат при неизменном окружении.
