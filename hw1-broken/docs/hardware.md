# Профиль оборудования и результаты

## Профиль

Замер выполнен на локальной машине с Python 3.12. Модель и параметры запуска
задаются в `params.yaml`.

Модель: `Qwen/Qwen3-0.6B`. Использован GPU-профиль: NVIDIA GeForce RTX 4060 Ti
с 8 ГБ VRAM. Модель загружена на `cuda:0` в формате `bfloat16`.

## Результаты замера

Команда `make bench` записывает три независимых показателя в
`docs/bench.json`:

- `load_time_sec` — время загрузки токенизатора и модели;
- `tokens_per_sec` — медианная скорость генерации после прогрева;
- `peak_rss_mb` — пиковая RSS-память процесса.

Замер выполнен командой `make bench` через Python 3.12 на GPU:

| Показатель | Значение |
| --- | ---: |
| Время загрузки, с | 4.43 |
| Скорость, токенов/с | 41.98 |
| Пиковая RSS, МБ | 2081.7 |

## Разбор найденных дефектов

## Где именно внесены изменения

Ниже указаны конкретные файлы и замены, которыми исправлены дефекты.

### Дефект 1: имя модели

Файл `src/model.py`, функция `load_model`:

```python
# было
name = "Qwen/Qwen3-0.6B"

# стало
name = params["model"]["name"]
```

В `src/generate.py` строка вывода модели также заменена с фиксированного
`Qwen/Qwen3-0.6B` на `params["model"]["name"]`. В `src/bench.py` поле
`report["model"]` теперь заполняется из того же параметра.

### Дефект 2: версии зависимостей

Файл `pyproject.toml`: записи без версий заменены на фиксированные версии:

```toml
torch==2.7.1+cu128
transformers==4.52.4
accelerate==1.7.0
numpy==2.2.6
pyyaml==6.0.2
```

После этого создан `uv.lock`, фиксирующий полный граф зависимостей.

### Дефект 3: неправильный замер tokens/sec

Файл `src/bench.py`, функция `main`:

```python
# было: один таймер включал загрузку модели
t0 = time.perf_counter()
tokenizer, model = load_model(params)

# стало: загрузка измеряется отдельно
load_started = time.perf_counter()
tokenizer, model = load_model(params)
load_time = time.perf_counter() - load_started
```

Перед измерениями добавлен прогрев `warmup_runs`, а для каждого запуска
генерации создан отдельный таймер. В итоговый отчёт записывается медиана
полученных скоростей.

### Дефект 4: отсутствие воспроизводимости

Файлы `src/generate.py` и `src/bench.py`: перед загрузкой модели добавлен вызов

```python
set_seed(params["generate"]["seed"])
```

Функция `set_seed` в `src/model.py` фиксирует состояния `random`, NumPy и
PyTorch. Поэтому sampling при ненулевой `temperature` даёт одинаковый результат
при повторном запуске в том же окружении.

### 1. Имя модели было захардкожено

**Что было.** Имя `Qwen/Qwen3-0.6B` находилось непосредственно в коде
загрузки, генерации и отчёта бенчмарка.

**Как проявлялось.** После замены `model.name` в `params.yaml` код продолжал
загружать Qwen3 и печатать старое имя. Это нарушало правило «единственная
точка правды» и делало выбор модели в конфиге нерабочим.

**Как исправлено.** `load_model`, генерация и отчёт используют
`params["model"]["name"]`; теперь имя модели хранится только в конфиге.

### 2. Зависимости не имели версий

**Что было.** В `pyproject.toml` были указаны только имена пакетов:
`torch`, `transformers` и остальные зависимости без версий.

**Как проявлялось.** На разных машинах `uv` мог установить разные версии
библиотек. Это меняло поведение генерации, а совместимость с CUDA и API
`transformers` не была гарантирована; сборка CI могла сломаться позже.

**Как исправлено.** Все прямые зависимости получили точные версии,
PyTorch зафиксирован как CUDA-сборка `2.7.1+cu128`, а `uv.lock` фиксирует
полный граф зависимостей и конкретные wheel-файлы.

### 3. В tokens/sec попадала загрузка модели

**Что было.** Таймер запускался до `load_model`, а затем использовался и для
первого запуска генерации. Прогрева перед замером не было.

**Как проявлялось.** Время загрузки модели включалось в расчёт
`tokens/sec`, поэтому скорость получалась искусственно низкой и зависела от
времени старта, а не только от скорости генерации.

**Как исправлено.** Загрузка измеряется отдельным таймером, затем выполняются
`warmup_runs`. Каждый измеряемый запуск имеет собственный таймер только вокруг
`generate`, а в отчёт попадает медиана скоростей.

### 4. Генерация не была воспроизводимой

**Что было.** В конфиге был указан `seed`, но код его не применял. При этом
ненулевая `temperature` включала sampling.

**Как проявлялось.** Два запуска одного и того же промпта могли выдавать
разный текст, несмотря на одинаковые параметры конфигурации. Такой результат
нельзя надёжно сравнивать в тестах и бенчмарке.

**Как исправлено.** Перед загрузкой модели и генерацией вызывается `set_seed`;
он фиксирует состояния `random`, NumPy и PyTorch. Поэтому при неизменном
окружении повторные запуски воспроизводимы, что подтверждает проверка
`tests/check.sh`.
