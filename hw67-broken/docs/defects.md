# Разбор дефектов стартового проекта

| Дефект | Причина | Исправление |
|---|---|---|
| Все конфигурации попадали в один run | Sweep создавал один вложенный `all-candidates` run и логировал в него результаты всех конфигураций | Для каждого кандидата создаётся собственный вложенный run непосредственно под родительским sweep. В run сохраняются параметры, метрики, артефакты и имя кандидата. |
| Файлы MLflow терялись при пересоздании контейнера | Объявленный volume `artifacts` не был подключён к сервису MLflow | Именованный volume подключён к `/mlartifacts`, совпадающему с `--artifacts-destination`. |
| Не фиксировались версии train/val | Sweep удалял `data_*` поля из provenance перед добавлением тегов дочерним run | Каждый run получает полный provenance, включая SHA256 train и val; выбор кандидата сверяет их с текущими файлами. |
| Порог loss можно было обойти | `promote` напрямую делил метрики и не вызывал проверку статуса run и лимита | До регистрации версии `promote` вызывает `gate`, который проверяет конечность метрик, завершение run и `val_loss / base_val_loss <= threshold`. |

После изменений прошли unit/pipeline тесты. Реальные sweep, сравнение моделей
и проверка сохранности между перезапусками локального MLflow server выполнены;
проверка named Docker volume недоступна без Docker Compose.
